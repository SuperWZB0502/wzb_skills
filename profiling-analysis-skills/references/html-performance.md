# HTML体积与浏览器内存优化

正常生成自动启用，无需Agent选择算法。已有结果执行统一入口`--render-only`；首次迁移会重建HTML载荷，此后复用载荷缓存。生成的HTML仍为一个文件，可直接离线打开，无CDN及旁置数据文件。

## 固化的处理

1. `compact_timeline.py`将每25000事件按列保存，重复文本使用共享字典，数值使用类型数组；缺失字段与null分别编码。
2. 时间使用精确整数基值/差值及原小数位数，超出JS安全整数的基值用BigInt读取，保留原始绝对/相对时间字符串；不降低时间精度。
3. `compact_timeline.js`创建轻量事件视图，绘图高频字段直接缓存，args等嵌套字段按访问需要物化。全部事件仍参与筛选、统计、FLOPs/MFU、CSV和详情。
4. 计算I/O引用按事件位置写入数值列，不再为全部计算事件构造以长事件ID为键的大型对象；输入输出记录仍共享。
5. 压缩块逐块读取并释放，删除已消费的内嵌JSON文本；ID索引只提前保存通信事件，用户点选计算事件时记录该事件。
6. 正式Python渲染器自动注入列读取器、数据和原有界面模板。canonical JSON/CSV不改变，Python和浏览器继续兼容旧gzip载荷。

## 真实样例对比

使用5_8_36、GBS3072的同一份解析结果：6个实采Rank，1,011,762事件。Linux aarch64 / Chromium 156.0.8078.4，1600×1150窗口。每个版本3次，交替先后顺序，每次独立浏览器进程，以下为中位数：

| 指标 | 原版 | 优化版 | 减少 |
| --- | ---: | ---: | ---: |
| HTML大小 | 53.13 MiB | 35.31 MiB | 33.5% |
| 首次可操作时间 | 7.95 s | 2.99 s | 62.3% |
| 加载后JS堆（强制GC后） | 552.55 MiB | 123.91 MiB | 77.6% |
| 加载后渲染进程RSS（强制GC后） | 829.10 MiB | 373.06 MiB | 55.0% |
| 加载阶段渲染进程RSS采样峰值 | 2198.20 MiB | 821.97 MiB | 62.6% |
| 整轮含交互的渲染进程RSS采样峰值 | 2198.20 MiB | 982.59 MiB | 55.3% |
| 显示计算流 | 3.39 s | 1.14 s | 66.4% |
| 再显示拷贝流 | 3.13 s | 1.04 s | 66.8% |
| 再显示Free | 2.78 s | 1.15 s | 58.4% |
| W缩放操作总耗时 | 2.86 s | 1.15 s | 59.6% |

加载时间定义为导航开始至数据ready且完成两次动画帧。JS堆在强制GC后读取，不包含类型数组的全部外部存储，应结合RSS看。RSS为50ms采样的渲染进程求和，可能重复计算共享页；它不等于整个桌面浏览器的唯一物理内存。没有清理OS文件缓存，结果不是磁盘冷读。短缩放只有少量动画帧，不将其p95换算成稳定FPS。其他机器/输入的绝对耗时和收益会变化；本轮没有重测首次后端trace解析。

## 无损与功能核对

- 第一份样例逐条核对1,011,762事件的全部字段、元数据和510,514个计算详情引用；第二份样例核对309,349事件和148,661个引用，均一致。
- 浏览器对两份样例的全部事件检查3个数值时间字段，与旧版`Number(原始时间文本)`完全一致；抽查144个跨Rank/流事件的全部字段。
- 1008个边界/随机事件通过Python及JavaScript读取核对，包括尾零、负时间、负零、超大绝对时间、缺失/null和嵌套字段。
- 3轮默认图和全部流图共6对截图逐像素一致，3对默认筛选CSV字节一致。
- 计算I/O、FLOPs/MFU、通信两表和固定浮窗、精确时间复制、f/b/L7r/opt详情、Ctrl框选重组与Esc恢复均通过。两个样例无浏览器错误和在线请求。

## 使用与复测

正常生成不增加依赖，仍使用既有Python入口。HTML浏览器需支持gzip DecompressionStream。可选全量核对工具为`validate_html_payload.py`；可选浏览器工具为`scripts/benchmark_html.py`，额外需要Playwright/Chromium与psutil。完整命令见[commands.md](commands.md)。结构化实测见[html-performance-results.json](html-performance-results.json)。

列式压缩减少文件和内存开销，仍需保留所有事件的列与时间索引，内存不会与事件数量完全无关。第一版全字段惰性读取曾使交互变慢，发布版已将高频字段直接缓存；未采用按需解压详情或切换Step时重新加载的方案，避免新增首次查看详情的等待。
