# 一、设计文档

# 设计文档 · 02-自检与定稿

- 角色：主特性

## 背景与目标

聊天结束时不能把开发中的改动误报为目录错误；但目录违规或发布输入未提交仍须拦截。

## 方案概述

日常检查单列待提交，手动检查默认严格。定稿前确认当前特性范围，提交已暂存内容和生成文档。

## 关键设计

开发、运行验收和技能发布使用不同目录，运行目录只接收经验证的源码提交改动。

## 风险与取舍

定稿不判断已暂存文件的业务归属，操作者需在事前审核暂存清单。

# 二、实现文档

# 实现文档 · 02-自检与定稿

- 角色：主特性

## 实现概述

`work-layout.mjs` 返回 `pending` 与 `errors`；聊天自检指定开发模式，手动检查默认严格。

## 关键改动

定稿事前检查目录和 Git 状态，仅追加暂存自己的合并文档；严格检查判定未跟踪和未提交文件。

## 配置与开关

无新增功能开关。

## 已知限制

技能发布仓库既有未提交文件留待发布任务处理。
