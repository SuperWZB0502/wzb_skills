# 同席 · 多智能体网页办公室

当前版本：**v1.14.2**（2026-11-15，对应工作根 `versions/` 最新记录；上游 Claw-Empire 版本见 `app/package.json`）。

把 Codex 和 Claude Code 放进一个私有网页工作台：为伙伴分配职能、服务和模型，在独立会话中协作，并把历史会话整理成公司知识库。它基于随包固定版本的 Claw-Empire 源码，部署到使用者自己选择的工作目录。

## 两种界面，同一套任务

- **任务动画（office）**：可见 Boss 办公室、会议室、工作区、休息区、知识库和小黑屋。角色按实际状态活动，经过门和走道；单击看信息、双击聊天、右键管理身份。
- **极简对话（chat）**：保留伙伴、服务、会话、知识库和任务操作，省去动画画布。两种界面互斥加载，切换会卸载上一页面；后台已提交的任务继续运行。

支持炭黑灰与奶白主题，同一浏览器记住选择。**空闲走动、休息和查看状态不调用模型，也不消耗模型 token**；浏览器绘制和状态同步仍使用资源。聊天、任务、会议发言与委派等实际模型调用会产生用量。

## 伙伴、任务与会议

Boss 是固定的个人入口，不可删除或开除；其他伙伴可设为 SE、PL、开发或测试，分别选择名称、Claw 外观、模型服务和思考档位。服务默认可以“稍后配置”，选定后再展开模型设置。

姓名旁的红、黄、绿分别表示工作、会议和休息；错误、等待输入等详情在信息卡或聊天进度中查看。任务进度用“接收任务、准备环境、执行任务、完成任务”四块箭头表示，只给已完成阶段填绿，工具详情默认折叠。可以停止任务，也可组织至少两位空闲伙伴依次从各自职能发言的会议，并查看会议记录。会议发言本身不修改项目或委派工作。

每个身份按自己的队列执行；应用不设置固定的全局任务并发上限。关闭聊天、断开隧道、退出网页或切换界面都不等于停止任务，需要结束执行时使用停止控件。

## 模型服务

在“我的模型服务”统一管理，明确选择 **Codex** 或 **Claude Code**；不根据模型名或服务地址猜执行器。所选执行器对应的 CLI 必须已安装在使用者的机器上，包内不携带外部 CLI 二进制或登录信息。

| 认证方式 | 使用方式                                                                                                           |
| -------- | ------------------------------------------------------------------------------------------------------------------ |
| API Key  | 在网页填写服务地址与 Key；Codex 使用 Responses，Claude Code 使用 Messages，可接兼容服务                            |
| 官方账户 | 不填写自定义中转 URL；Codex 显示本次官方设备授权地址/验证码，Claude 使用官方 PKCE 链接并把返回的授权码填回专门表单 |

打开授权网站不等于登录完成，以网页返回的认证状态为准。Key、OAuth token 和临时授权资料只在运行期内存中处理，重启后重新提供 Key 或授权；不要发送到聊天或写进配置文件。网页配对登录与模型认证分开：同一浏览器的有效登录可以跨重启保留 30 天。

聊天模型从所选服务目录下拉选择，可刷新；目录不可用时保留当前模型兜底，身份编辑器仍可手填模型 ID。“应用配置”只影响后续任务，正在运行的任务保留启动时的配置。

Claude Code 单独提供 **1M 长上下文** 手动勾选项：有模型时才能勾选，界面显示基础模型 ID，保存时保留兼容的上下文后缀。请先确认服务和模型支持；勾选不是容量探测，也不承诺实际支持百万 token 输入。

删除模型服务会自动把引用它的伙伴改为“稍后配置”，会话保留；已经开始的调用继续使用原配置直到结束。

## 独立会话与公司知识库

每位伙伴有自己的会话列表，可新建、切换和复制 ID。消息、进度与原生 CLI 线程按会话隔离，历史和线程映射保存在已选工作根内，重启保留。切换会话不会停止任务。

知识库按伙伴分组，支持搜索、分类/成员筛选、标题和分类编辑，先显示概要、最近使用和真实读取记录，明确打开详情才加载正文。只有主动选择，才把其他会话作为只读快照加入当前上下文：最多四个来源，每源最近 12000 字符，截断会有说明；也支持通过工具按会话 ID 分段读取并记录实际读取者。

员工身份分两步处理：正式员工“删除身份”后移入小黑屋，保留配置和历史；只有在小黑屋中“开除员工”才清除配置并从名单消失。会话、原生历史和公司项目成果继续保留，知识库保留原作者的最小归属信息。**身份处理与永久删除会话是不同操作。** 永久删除会话需明确确认；清理失败保留待处理记录，在知识库显式重试，不能把待清理当作已全删。

## 阅读、输入和图片

回复支持 Markdown 标题、强调、列表、引用、表格、行内代码及代码块。代码块右上角可复制正文，保留缩进换行，成功或失败都有提示；宽代码和表格可横向滚动。远程 Markdown 图片以链接按需打开，上传附件保留独立预览。

聊天内容区可全屏阅读，按 **Esc** 或“退出全屏”返回；退出阅读全屏后聊天仍保留。浏览器不支持原生全屏时使用网页视口回退。

**Enter 发送，Alt + Enter 换行**；输入法组词时的 Enter 只确认候选。可选择图片、粘贴截图或拖入图片，检查预览后发送。支持 PNG/JPEG/WebP，每张不超过 5 MiB、40 MP，每次最多四张；实际视觉理解取决于服务和模型，并可能产生额外用量。

## 长期记忆、技能库与项目目录

- **两级长期记忆**：`company/rules.md` 是全员规章；每个员工还有 `agents/<id>/profile/memory.md`（受管规章区块 + 角色资源 + 自己维护的约定），每次运行自动注入（上限 6000 字符）。改规章后下一次运行自动同步；`docs/dev-work-layout.md` 按需读取，不注入全文。
- **技能库**：`skills/` 遵循 Anthropic Agent Skills 规范、按方向分类（`skills/<方向>/<技能>/SKILL.md`）；agent 用 `office_list_skills` 查看、`office_read_skill` 读取（支持“方向/技能名”）。改完执行 `node app/scripts/skills-index.mjs <根>` 更新索引。
- **项目目录（开发岗）**：`work/<编号-项目>/` 下分 `code/`（独立 git 仓库）、`test/`（实验中间产物，不进 git）、`feature/`（设计/实现/测试文档）；特性最多两级，提交以主特性为最小粒度。用 `node app/scripts/work-layout.mjs` 生成骨架并检查。
- **备份**：`node scripts/office.mjs backup --root <根> [--keep 7]` 生成 `artifacts/backups/*.tar.gz`（SQLite 在线快照 + 原生会话 + agents/projects/skills），服务进程内每 24 小时自动备份；`/healthz` 会返回 `backup.at/ok` 与执行器状态。
- **会话存储**：每个员工一个根目录 `agents/<id>/{profile,sessions,work,cache}`；从旧布局升级用 `office.mjs migrate-layout --mode plan|apply|rollback`（服务必须停止，可回滚）。

## 从哪里开始

首次使用先选择自己的工作目录和默认界面，再由 [SKILL.md](SKILL.md) 按脚本流程安装。已有安装继续使用保存的工作根，避免重装覆盖。应用状态、项目、缓存、临时文件和产物均留在该根内。

运行环境需要 Node.js 22+（含 `node:sqlite`）及相应模型 CLI；原生会话文件清理目前要求 Linux。服务默认仅监听回环地址，通过使用者自己的 SSH 隧道访问，VS Code 是可选项。新安装默认使用受限执行方式；其他机器的 account 模式授权、全局 CLI 配置和认证状态不随包继承。

这里介绍随包源码具备的功能。具体包内容以源码清单和哈希为准；静态检查、离线核验、短模型连通、浏览器验收和新环境安装是不同证据。不要把旧包安装结果、模型目录可见或短请求成功当作本轮完整功能、OAuth、视觉或 1M 容量已经验证。当前包的最终验收结果应以实际报告为准。

服务器重启后，在工作根运行 `bash restart-office.sh` 可启动并检查服务，再于网页重新提供 API Key 或完成模型账户授权。安装器会把此脚本放在用户选择的工作根顶层。

## 阶段产出

可分发的 skill 由项目代码仓库维护：`pack-source.mjs`（白名单收集源码）→ 在 skill 仓库提交 `chore(skill): sync source @<根短哈希>` → `package.mjs --skill` 出 ZIP。完整命令见 [脚本工作流](references/workflows.md)。
