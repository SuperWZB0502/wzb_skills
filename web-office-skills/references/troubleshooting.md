# Known integration issues

These notes come from the pinned implementation's deployment. Diagnose the actual failure before applying a workaround; do not copy this development host's authorization or machine-specific paths.

- **bwrap / user namespace failure:** an HTTP health check or simple model response does not prove terminal tools can start. Some shared Linux servers disable namespaces required by Codex sandboxing. Preserve the default sandboxed mode until that installation's user explicitly accepts account execution, as described in SKILL.md. Read-only meetings still prohibit terminal writes and delegation.
- **CLI version differences:** source review used Codex CLI 0.167.1 and Claude Code 2.1.311 metadata. A service requires its chosen executor’s CLI; use `CLAUDE_CLI` or PATH for a colleague’s Claude binary. Local `workspace.json` may also select a nonsecret `cliPaths["claude-code"]`; the package includes no external CLI binary or login material. Do not run someone else’s launcher or read its auth/settings. Native MCP function calls use namespace `mcp__office`; the bounded office server's tool approval setting is scoped under `mcp_servers.office`. Inspect the installed CLI help/schema if a different version rejects configuration, rather than changing global authentication or approval settings.
- **Shell tool still running:** a native exec response may return a session ID before completion, especially with a login shell. Wait for its real completion before checking outputs. A missing output immediately after a session response does not establish a permission failure.
- **Project preparation:** explicit committed Git projects use stable per-agent worktrees under `projects/.worktrees/`. A first checkout rejects a dirty source. Reusing an existing worktree preserves that agent's edits. Git repositories with command filters or conditional include configuration are rejected by the preparation path; inspect the repository configuration before removing such features, or use an ordinary imported task folder. Git calls have cancellation and a bounded preparation timeout, separate from the user's optional model task timeout.
- **Source package freshness:** regenerate the skill source archive after the final runtime/UI fixes. Its manifest inventories actual files, including uncommitted additions. An earlier clean-install result does not prove a later source tree is present in that archive.
- **Optional cache seeding:** pnpm's store can contain `v10/projects` links back into installed projects. Do not recursively dereference the whole store when warming another workspace: it can copy source trees and follow dependency links repeatedly. Reuse only the content-addressed `files` and `index` directories, leave project bookkeeping to that installation, and keep the destination cache inside its selected root. Normal installation can simply download into its own cache.
- **Long workspace paths:** the `tsx` CLI wrapper creates an absolute IPC socket beneath TMPDIR and can exceed the Unix socket pathname limit even when the office control socket itself is relative. The launcher uses Node's `--import` with the installed tsx loader directly. Preserve that launch form; do not work around the error by moving temporary files outside the user's workspace.
- **Restart boundaries:** frontend/policy live updates retain keys and tasks. A real core/runtime restart clears model Keys/OAuth credentials and interrupts tasks; it preserves saved messages and valid fixed 30-day browser logins, and closes interrupted meetings. Enter the model Key again or repeat official account authorization in the webpage. Upgrading from memory-only browser sessions requires one fresh pairing; ordinary later restarts do not. Logout revokes the current browser login.

Keep the deployment work log factual: record the original error, inspected evidence, local correction, completed command result and any remaining limitation. Do not include credentials in diagnostics or request that the user send a key in chat.

## Interaction and session symptoms

- **Pairing requested again:** distinguish an expired/revoked login, cleared browser cookies or a new browser profile from missing model credentials. The old memory-only login is not migrated into the persistent store, so the first upgrade needs one fresh pairing. A service restart alone retains an unexpired persistent login.
- **Model change did not take effect:** select the model and a supported effort (or model default), then click Apply in the chat header. An in-flight call keeps its captured configuration; saved changes apply to subsequent execution. A visible model ID proves directory access, not the selected executor's Responses/Messages or vision compatibility.
- **Enter/IME behavior:** Enter sends, Alt+Enter inserts a newline, and composition-confirmation Enter must not submit. Preserve these bindings when adapting the UI; use the visible send control while diagnosing a platform-specific input issue.
- **Progress looks brief or slow:** updates are bounded text activity, with up to 400 recent items per agent and 6000 characters of detail per item; ongoing updates for one item are throttled to 250 ms. Generic thinking activity intentionally contains no raw internal reasoning. This is not terminal-video streaming or an unlimited terminal transcript. A short progress record does not prove a task stopped.
- **Image cannot upload:** inspect the visible error, image signature and dimensions. Supported input is PNG/JPEG/WebP, at most 5 MiB and 40 MP per image, four images per message. Remove or retry failed preview items before sending. Agent attachments are saved beneath `agents/<id>/attachments/`; removing a draft preview is not a promise of server-file deletion.
- **A later image turn is too large:** proxy request bodies are capped at 32 MiB. Historical image inputs and Base64 overhead can exceed this even when each new upload meets its own limits. Reduce image dimensions/size or use a separate new conversation; the per-agent conversation selector can create an independent conversation while preserving old conversations for later selection.
- **Image uploaded but model did not interpret it:** distinguish file/CLI transport from the chosen service's vision support and billing. Check the real model response without claiming that a local controlled-model result proves remote vision inference.
- **Theme reset:** first visit defaults to dark; the top theme switch offers the warm cream light palette. The choice is nonsecret browser-local state, so another browser or cleared site storage can reset it.

## Service authorization and cleanup

- **Account login appears pending:** opening a URL is not completion. Use the actual current device URL/code for Codex or complete Claude’s official PKCE page and paste the returned code into the dedicated form. Backend state determines completion. A blocked popup leaves an explicit link; never replace it with a guessed URL or ask for secrets in chat.
- **Wrong protocol:** select the executor explicitly. Codex API mode requires Responses; Claude Code API mode requires Messages. A custom API proxy URL does not become a supported account OAuth endpoint.
- **Permanent delete reports pending:** refresh metadata and inspect “存储清理未完成”. A journal may exist before DB deletion, so the record may still exist or may already be removed. The message is not proof of complete deletion or of no deletion. Retry only through the explicit cleanup button; unknown native formats can fail again and retain the journal. Do not manually remove journals, another agent’s generated messages or user project artifacts. See [cleanup boundaries](services-conversations.md).
- **New executions temporarily blocked during cleanup:** affected agents/account providers are maintenance-locked while cleanup runs. This is not a global fixed concurrency cap.
