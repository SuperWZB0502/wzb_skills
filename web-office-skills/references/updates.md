# 更新、前端发布与回滚

命令和参数统一维护在 [workflows](workflows.md)。已有实例沿用 `workspace.json`，不能用首次安装器覆盖。只使用用户明确提供的可信本地源码/发布包，不自动 pull 未核对的上游版本。

## 选择路径

| 变化                                                  | 采用方式                                          |
| ----------------------------------------------------- | ------------------------------------------------- |
| 只有网页源码，运行层未变化且内建前端仍是实际服务入口  | build 暂存并核对结果，再显式 publish-frontend     |
| 有符合运行层 release 格式的前端/纯策略包              | 生命周期 update；需要时 rollback 到保留的 release |
| 核心、依赖、Node、运行 ABI 或数据库 schema 不兼容变化 | 计划重启后更新，不能冒充前端热发布                |

build 从不激活。publish-frontend 要求 receipt/哈希、当前后端指纹和运行身份符合，先保存备份、发布新 assets，再原子替换入口 HTML，保留旧 hashed assets；不重启运行层或清内存模型凭据。拒绝条件需按实际原因处理，不能绕过检查手工复制。

生命周期 update 支持的纯策略模块为 `agent-summary` 和 `role-prompts`。它们不持有 vault、数据库或任务进程；worker 隔离模块生命周期，不是给不可信代码的安全沙箱。只安装可信本地变更。release 包含带哈希的 manifest、双入口 frontend 与可选 hot 模块；ABI/schema 不兼容会要求重启。哈希证明内容完整性，不证明发布者身份。

成功热更新保持 PID/boot、任务和内存凭据；已运行任务保留启动配置/策略，新任务使用已应用的新配置。以真实控制接口、HTTP 和脚本返回结果确认激活，不用命令文本或 fixture 充当在线证据。回滚切换保留的前端/策略，不恢复已丢失的 Key，也不撤销用户项目变更。

计划重启会中断受管任务、清除 Key/OAuth，历史和有效浏览器登录保留；用户在网页重新补 Key 或授权。部署前先核对任务状态，保留可回退版本与真实结果。

分享包由 package 重新生成当前源码清单/哈希，再用 verify/privacy-scan 核验。离线结构/哈希结果、实际构建、全新安装和浏览器验收分别记录；第一版或其他历史包的结果不能证明当前包通过。
