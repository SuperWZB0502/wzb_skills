# 一、设计文档

# 08-交付链接锚点 · 设计文档

## 问题

聊天里的相对链接 `./...年度答辩.html#8` 点击后返回 `{"error":"file_not_found"}`。

失败 URL 的 `path` 参数尾部是 `...%E5%B9%B4%E5%BA%A6%E7%AD%94%E8%BE%A9.html%238`。

## 根因

`workspaceFileUrl(agentId, href, mode)` 把整条 href 一次编码：

```ts
const path = decodeHref(href).trim().replace(/^\.\//, "");
return `.../files?path=${encodeURIComponent(path)}&mode=${mode}`;
```

`#8` 于是成为路径的一部分（`%238`），`workspace-files.ts` 按真实文件名解析必然 404。同样地，`?v=2` 这类查询串也会被并进 path。

## 设计取舍

| 方案 | 结论 |
| --- | --- |
| 简单删掉 href 里所有 `#` 之后的内容 | 否：会把编码过的 `%23`（文件名里真正的 `#`）一起砍掉 |
| 先 `decodeURIComponent` 再切 `#` | 否：`a%23b.html` 会被误判为「文件 a」+「锚点 b.html」 |
| **先按原始 `#`、`?` 切分，再对 path 解码一次** | 采用：编码文件名不受影响，锚点语义与浏览器一致 |
| 锚点塞进 API 查询参数 | 否：服务端不消费，且会与 `path`/`mode` 冲突 |
| **锚点追加在 API URL 末尾（fragment）** | 采用：fragment 不会发给服务端，预览页可读 `location.hash` |

## 语义划分

- `path`：工作区相对路径，解码一次、去掉前导 `./`，只此一项进入 API 的 `path`。
- `query`：不进入 API（服务端无对应语义），避免把 `chart.png?v=2` 当文件名。
- `fragment`：追加在浏览器 URL 末尾；`encodeFragment()` 只转义 fragment 放不下的字符（控制字符、空格、`"#<>\\^`|{}`），`#8`、中文锚点保持可读。

## 安全

`isWorkspaceFileHref()` 改为校验 path 部分：拒绝绝对路径、协议头、反斜杠、`\0`、`.`/`..` 段；解码后的 path 也复核（`%2E%2E` 这类编码穿越在客户端就被拒）。服务端 `normalizeRelativeFile()` 的校验保持不变，作为第二道防线。

## 影响面

仅前端链接渲染：`MessageBody`（会话正文、Markdown 预览内文）与 `MarkdownPreviewDialog`。服务端接口契约、CSP、下载语义均未改。

# 二、实现文档

# 08-交付链接锚点 · 实现文档

提交：`a6236c8 fix(01-网页办公室): 08-交付链接锚点`（版本 v1.17.2）

## 1. `file-links.ts`

### 新增 `splitWorkspaceHref(href)`

```ts
export function splitWorkspaceHref(href: string): WorkspaceHrefParts {
  const value = href.trim();
  const hashAt = value.indexOf("#");
  const head = hashAt < 0 ? value : value.slice(0, hashAt);
  const fragment = hashAt < 0 ? "" : value.slice(hashAt + 1);
  const queryAt = head.indexOf("?");
  const rawPath = queryAt < 0 ? head : head.slice(0, queryAt);
  return { path: decodeHref(rawPath).trim().replace(/^\.\//, ""), fragment };
}
```

先切分后解码：`a%23b.html` 的 `%23` 不会被当成锚点分隔符，path 解出 `a#b.html`，再由 `encodeURIComponent` 编码回 `a%23b.html`。

### `workspaceFileUrl()`

```ts
const { path, fragment } = splitWorkspaceHref(href);
const url = `/api/office/agents/${encodeURIComponent(agentId)}/files?path=${encodeURIComponent(path)}&mode=${mode}`;
return fragment ? `${url}#${encodeFragment(fragment)}` : url;
```

无锚点时输出与旧实现逐字节一致（既有用例断言仍然成立）。

### `encodeFragment()`

逐字符判断：码点 ≤ 0x20（含空格）、0x7f、以及 `" # < > \ ^ ` | { }` 转成 `%XX`；其余（含中文、`/`、`?`、`=`、`&`）原样保留。

### `isWorkspaceFileHref()`

校验对象从「整条 href」改为「path 部分」，并复核解码后的 path（拒绝 `/` 开头、协议头、`\`、`\0`、`.`/`..` 段）。

### `resolveRelativePath()`

改为 `splitWorkspaceHref()` 取路径，锚点原样拼回结果末尾，供上层继续走 `workspaceFileUrl()`（`..` 逃逸仍然返回 null）。

## 2. `MessageBody.tsx`

- 非 Markdown 链接：`fileModeOf(path)` 决定「在线打开/查看/下载」，`href` 用 `workspaceFileUrl(target)`（内部已拆锚点）。
- Markdown 链接：`onPreview(path)` 传去锚点路径，避免弹窗标题与请求 URL 带 `#8`。

## 3. 未改动

- `MarkdownPreviewDialog.tsx`（其 `workspaceFileUrl(agentId, path, "download")` 自动受益）。
