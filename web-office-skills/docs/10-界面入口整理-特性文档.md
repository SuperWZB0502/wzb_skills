# 一、设计文档

# 设计文档 · 10-界面入口整理

## 目标

1. 「压缩上下文」的确认与结果反馈完全由站点负责，不再出现浏览器原生对话框。
2. 平台右上角系统栏不再放「添加伙伴」这类功能入口（侧栏已有 ＋），改为唯一需要系统级权限的动作：重启服务。

## 方案

### 1. 统一的站内确认弹窗

新增 `ConfirmDialog`，基于现有 `Modal`（已有焦点限制、Esc 关闭、遮罩点击关闭）。它只负责：标题/副标题、说明区、可选的错误行、`取消 / 确认` 两个按钮，以及 `busy` 时禁用两个按钮并把确认按钮文案切成「处理中…」。

不引入新依赖，也不改 `Modal` 的行为：`Modal` 是站内所有对话框的共同底座，改它风险大。

### 2. 压缩确认改为站内弹窗

`ConversationControls` 里原来的 `window.confirm` 直接替换为 `ConfirmDialog`。开关关闭时保留旧行为（`window.confirm`）作为回退，便于出问题时用环境变量退回，不需要改代码。

失败原因不再写到页面级 `error`（那里同时承载复制/重命名等错误），改为弹窗内的 `compactError`，弹窗保持打开、确认按钮恢复可点，直接重试。

### 3. 重启服务：两个仓库边界内的最小实现

重启的难点是"服务自己杀自己"：

- **谁执行**：浏览器只调接口，接口把活儿交给工作区 CLI（`scripts/office.mjs restart`）。CLI 先 `control("stop")` 停止旧运行时并等 pid 真正退出（端口随之释放），再走原有的 `start` 路径拉起新运行时并校验身份。
- **顺序**：接口先写响应（202），250ms 后再拉起 detached 的 CLI 助手；CLI 助手在 stop 前再等 500ms。两级延迟保证浏览器能收到 202，不会因为进程退出而拿到网络错误。即使 202 丢了，前端也不会误判：它以"`bootId` 变了"作为成功判据。
- **护栏**：任何 run 在跑就返回 409（`restart_blocked_active_runs`），绝不硬杀任务。
- **凭据**：重启清空内存凭据，弹窗必须写明；这是刻意保留的安全属性，不做持久化。
- **开关**：`OFFICE_FEATURE_UI_RESTART=0` 时接口 403、快照 `features.restart=false`；前端**只在快照明确为真时**显示按钮——旧运行时不带该字段，就不会出现"点了报错"的按钮。

## 风险与回滚

| 风险 | 处理 |
| --- | --- |
| 重启打断正在运行的任务 | 服务端 409 拒绝；只有在空闲时才会执行 |
| 重启后需要重新填 Key | 弹窗明示；CLI 拉起的新运行时不含任何继承的凭据环境变量 |
| 重启失败（端口未释放 / 启动超时） | CLI 返回 `runtime_stop_timeout`、`runtime_restart_identity_unchanged` 等明确错误；前端轮询 120 秒超时后提示手动 `bash restart-office.sh` 并查看 `logs/runtime.log` |
| 旧服务端 + 新前端 | 按钮条件为 `features.restart === true`，旧快照没有该字段 → 按钮不出现 |
| 想彻底撤掉重启入口 | `OFFICE_FEATURE_UI_RESTART=0` 重启一次即可；接口与按钮同时消失 |

## 接口

```
POST /api/office/admin/restart     （需登录 Cookie + X-CSRF-Token）
202 { restarting: true, bootId, activeRuns: 0 }
403 { error: "restart_disabled" }              开关关闭
409 { error: "restart_blocked_active_runs" }   有任务在跑
```

```
node scripts/office.mjs restart --root <工作根>
{ restarted: true, wasRunning: true, previousBootId, bootId, pid, origin, ... }
```

## 关键实现点

- **响应先于停机**：`res.status(202).json(...)` 之后 `setTimeout(…, 250).unref()` 才拉起 CLI；CLI 在 `stop` 前再等 500ms。
- **身份校验**：CLI 用 `identified()` 确认控制 socket、`state/runtime.json`、pid 三者一致才动手；stale 元数据 + 存活 pid 直接 `runtime_identity_unverified`，绝不盲杀。
- **环境隔离**：`spawnRestart` 与 `start` 同样剥离 `*API_KEY* / *TOKEN* / *SECRET* / *PASSWORD* / *AUTHORIZATION*` 环境变量。
- **前端判据**：轮询 `GET /api/office/snapshot`，`bootId` 变化即 `location.reload()`；网络错误视为"还在重启"继续等，120 秒未恢复则提示手动重启。
