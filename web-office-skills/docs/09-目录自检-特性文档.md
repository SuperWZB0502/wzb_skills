# 一、设计文档

# 设计文档 · 09-目录自检

- 角色：主特性

## 背景

目录规范与"每个主特性定稿即提交"的约定写在 `company/dev-work-layout.md` 里，但执行靠自觉：`check` 曾经默认检查"当前目录"，在仓库根跑等于扫一个不存在的路径，永远返回 ok；工作区顶层杂物（如 `work/out/`）也从不报错。

## 目标

1. 检查可执行、结果可信：跑一次就知道哪里不合规；
2. 不越界：一个 agent 只查自己的工作区；
3. 不打扰：问题只在失败时说一次，不占上下文。

## 方案

- **定位**：从 cwd 向上找到 `agents/<id>/work`；仓库根运行时提示用 `--work`；`--all` 仅供人/管理员排查。
- **顶层白名单**：只允许 `README.md`、`code/`、`test/`、`feature/`、`NN-名称/`，其余报 error 并提示归位。
- **提交约定**：`code/.git` 必须存在；已跟踪文件有未提交改动 → error；未跟踪文件 → warning（避免把运行产物当违约）；主特性有「已采纳」条目必须有《特性文档.md》，`code/docs/<特性>-特性文档.md` 必须已被 git 跟踪。
- **运行期提醒**：chat 运行成功结束后调用同一脚本，失败才推一条系统消息；按会话记住上次内容，同一问题不重复，检查通过则清除记忆（下次再坏会重新提醒）。

# 二、实现文档

# 实现文档 · 09-目录自检

- 角色：主特性

## 脚本侧（`app/scripts/work-layout.mjs`）

| 函数 | 作用 |
| --- | --- |
| `ownWorkRoot()` | 从 cwd 向上匹配 `agents/<id>/work` |
| `checkWorkRoot(root)` | 顶层白名单 + 逐项目检查，输出里带 `checked` 根路径 |
| `gitChanges(repo)` | `git status --porcelain`（`core.quotePath=false`）拆成 modified / untracked |
| `isGitTracked(repo, path)` | `git ls-files --error-unmatch` 判断文档是否已提交 |
| `checkProject(project, root)` | 目录结构、文档齐全、状态合法、提交约定 |

## 运行侧（`app/server/office/run-registry.ts`）

- `layoutSelfCheck(agentId, record, work)`：`execFile(node, [<root>/app/scripts/work-layout.mjs, check], {cwd: work, timeout: 8s})`；
- 仅 `kind === "chat"`、未取消、脚本存在时执行；`OFFICE_FEATURE_LAYOUT_SELFCHECK=0` 可关闭；
- 失败时组装最多 3 条错误（去掉工作根前缀、截断 320 字）推系统消息；
- `layoutNotice: Map<conversationId, content>` 去重：内容相同不再推，检查通过则删除记忆。

## 成本

检查是纯文件系统 + git 调用，**不调用模型**；成功时不产生任何消息，失败时才有一条几百字系统消息。
